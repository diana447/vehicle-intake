# Vehicle Intake

Бэкенд для записи машин на приёмку склада. Дистрибьютор выбирает склад и дату, загружает Excel со списком VIN, а сервис проверяет каждую машину и записывает те, которые проходят проверки и помещаются в дневной лимит склада. По каждой строке файла возвращается результат.

Стек: Python 3.12, FastAPI, PostgreSQL 16, SQLAlchemy 2.0 (async), Alembic, Pydantic, httpx, openpyxl.

## Что умеет

| Эндпойнт | Что делает |
|---|---|
| `GET /storehouses` | список складов, которые видит пользователь |
| `GET /storehouses/{id}/calendar?year=&month=` | по каждому дню месяца: занято и свободно, включая дни без записей |
| `GET /storehouses/{id}/availability?date=` | «свободно N из M» на выбранную дату |
| `POST /storehouses/{id}/entries/upload?date=` | загрузка Excel и запись машин |

Права: Астана Моторс (`company`) видит и пишет на любой склад, дистрибьютор (`distributor`) только на свои. Чужой склад для него не существует (ответ 404).

## Что нужно для запуска

- [uv](https://docs.astral.sh/uv/) (сам поставит нужный Python 3.12)
- Docker с docker compose

## Запуск

Все команды из корня проекта, если не написано иное.

```bash
cp .env.example .env              # настройки; для локального запуска менять ничего не нужно
uv sync                           # зависимости
docker compose up -d              # PostgreSQL на порту 5440
```

Таблицы и тестовые данные (из папки `src`):

```bash
cd src
uv run alembic upgrade head       # миграции
uv run python -m scripts.seed_data   # организации, склады, записи
```

Сервис учёта в задании чужой, поэтому здесь запускается его **мок** (из корня, в отдельной вкладке терминала):

```bash
uv run uvicorn mock_accounting.main:app --port 8001
```

Сам сервис (из папки `src`):

```bash
uv run uvicorn main:app --reload
```

Swagger: http://127.0.0.1:8000/docs

Если порт 8000 занят (например, другим контейнером), запустите на другом: `--port 8010`.

Сид можно запускать повторно: если данные уже есть, он ничего не делает. Чтобы начать с чистой базы: `docker compose down -v`, затем снова `docker compose up -d` и миграции.

## Как проверить

### 1. Получить токены

Логина по заданию нет, токены выпускает скрипт (из папки `src`):

```bash
uv run python -m scripts.issue_token astana          # Астана Моторс
uv run python -m scripts.issue_token distributor-a   # Степь Моторс, склад Астана-1
uv run python -m scripts.issue_token distributor-b   # Алатау Авто, склады Алматы-2 и Шымкент
```

В Swagger нажмите **Authorize**, вставьте токен (только сам токен, без слова Bearer) и подтвердите.

### 2. Тестовые данные

| Склад | Владелец | Лимит в день |
|---|---|---|
| Астана-1 | Степь Моторс | 5 |
| Алматы-2 | Алатау Авто | 3 |
| Шымкент | Алатау Авто | 10 |

В базе уже есть записи на несколько дней, поэтому календарь не пустой. Лимиты маленькие специально, чтобы легко проверять «Не хватило мест».

### 3. Что стоит попробовать

| Действие | Ожидаемый результат |
|---|---|
| `GET /storehouses` без токена | 401 |
| то же с токеном `distributor-a` | один склад, Астана-1 |
| то же с `astana` | три склада |
| календарь склада 1 с токеном `distributor-b` | 404, чужой склад |
| «свободно» на любой день без записей | `occupied: 0`, `free: 5` |
| загрузка `sample_vehicles.xlsx` на будущую дату | 5 записано, 5 отклонено, по разным причинам |
| тот же файл ещё раз | 0 записано, прежние машины получают «Уже есть активная запись» |
| дата в прошлом | 400, `past_date` |
| остановить мок учёта и загрузить файл | 503, ничего не записано |

Для проверки 503 можно не останавливать мок, а запустить его с отказом: `MOCK_ACCOUNTING_DOWN=1 uv run uvicorn mock_accounting.main:app --port 8001`.

### Пример файла

`sample_vehicles.xlsx` в корне проекта. В нём есть все случаи, которые показывает дизайн:

| Строка | Что проверяет |
|---|---|
| 2, 3, 8-11 | обычные машины (часть не влезет в лимит склада) |
| 4 | VIN из 16 символов: «Неверный VIN» |
| 5 | машины нет в учёте |
| 6 | у VIN уже есть активная запись (из сида) |
| 7 | повтор строки 2 |

Загрузить можно и из терминала:

```bash
curl -X POST "http://127.0.0.1:8000/storehouses/1/entries/upload?date=2026-12-15" \
  -H "Authorization: Bearer <токен distributor-a>" \
  -F "file=@sample_vehicles.xlsx"
```

Дата должна быть не в прошлом.

## Excel-файл

- формат `.xlsx`, до 1 МБ, до 200 строк с VIN;
- первая строка это заголовок, в ней столбец с названием `VIN` (регистр и пробелы не важны, положение столбца любое);
- остальные столбцы игнорируются, пустые строки пропускаются;
- номера строк в ответе такие же, как в Excel: заголовок это строка 1.

## Ответ загрузки

```json
{
  "storehouse_id": 1,
  "date": "2026-12-15",
  "total_rows": 10,
  "booked_count": 5,
  "rejected_count": 5,
  "entries": [
    {"row": 2, "vin": "LVVDB21B4RD012415", "status": "BOOKED", "reason": null},
    {"row": 4, "vin": "Z94C241BBRR10887", "status": "REJECTED", "reason": "Неверный VIN — 16 символов"}
  ]
}
```

Три экрана из дизайна строятся из одного ответа: все записаны (`booked_count == total_rows`), записаны частично, не записано ничего (`booked_count == 0`). Ошибки на весь запрос (плохой файл, дата в прошлом, учёт недоступен) приходят как `{"detail": "...", "code": "..."}` со статусом 400 или 503.

## Как работает загрузка

1. Находим склад с учётом прав, чужой даёт 404.
2. Проверяем дату (не в прошлом).
3. Читаем Excel.
4. Отсеиваем VIN неверной длины и повторы в файле.
5. Один запрос в сервис учёта по всем VIN.
6. Один запрос в базу: у каких VIN уже есть активная запись (на любом складе).
7. Берём блокировку на пару «склад + дата», чтобы параллельные загрузки не превысили лимит.
8. Считаем занятые места уже под блокировкой.
9. Места раздаём по порядку строк файла, остальным «Не хватило мест».
10. Один `commit` на всю загрузку.
11. Отдаём результат по каждой строке в порядке файла.

Строка получает первую сработавшую причину отказа: длина VIN, повтор в файле, нет в учёте, уже есть запись, не хватило мест.

## Защита от гонок

- **Лимит склада.** Блокировка `pg_advisory_xact_lock` по ключу «склад + дата». Вторая загрузка на тот же день ждёт первую, потом заново считает занятые места. Блокировка снимается сама после `commit`.
- **Одна активная запись у VIN.** Частичный уникальный индекс `uq_entries_active_vin` (только где `status = 'ACTIVE'`). Если один VIN параллельно загрузили на два склада, индекс пропустит одну запись, а вторая загрузка получит 409.

## Допущения

- Порядок причин отказа выбран мной, в задании он не описан (см. выше).
- Если VIN повторяется в файле, дальше идёт первое вхождение, остальные отклоняются.
- Длину VIN (17 символов) проверяем сами, до обращения в сервис учёта.
- Название столбца ровно `VIN`, как в задании. Другие названия (`ВИН` и подобные) не принимаются.
- Запись на сегодняшний день разрешена, на прошедшие нет. «Свободно» и календарь можно смотреть и для прошлых дат.
- Если сервис учёта недоступен, ничего не записывается (503).
- Лимит склада это колонка `daily_limit`. Склады создаются сидом, эндпойнта создания в задании нет.
- Токен проверяется по общему секрету (HS256), как просит задание. В проде здесь был бы Keycloak и RS256.
- Тексты ошибок обычные константы, без перевода.

## Что не сделано

- Тесты (в задании не нужны).
- Скачивание шаблона Excel и отмена записи (в задании нет).
- Фоновая обработка больших файлов: загрузка синхронная.
- Защита от «zip-бомбы» в `.xlsx` (ограничен только размер самого файла).
